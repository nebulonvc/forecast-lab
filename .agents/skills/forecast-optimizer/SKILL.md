# Forecast Optimizer（数据驱动预测方法优化与新技术同构校准）技能指南

当用户提出一个预测直觉、评估某项新技术“这次是否不一样”、希望改进预测准确度，或在新增证据后做概率更新时，启用本技能。

> **两条核心交付铁律**：
> 1. **必须把预测方法写出来**：最终向用户交付或写入账本的每一条预测，绝不允许只给裸结论或孤立概率，必须将 **【预测结论 + 显式预测方法（主方法名称 + 四步推导链 + 反校验透镜 + 承诺硬度依据）+ 全库校准概率 + 领先指标 + 证伪红线】** 作为整体一并写出。
> 2. **评估新技术必须做“历史同构骨架 × 当下实时参数”双校准**：凡涉及 AI、机器人、自动驾驶、芯片、能源、生物科技等技术扩散判断，必须用引擎内置的 **150 年 12 次技术浪潮 Bass 扩散曲线（`evaluate_tech_differentiation`）** 检验“这次是否不一样”（识别所属四层摩擦层级与存量折旧底线），并联网核查引擎列出的 **3 项当下实时瓶颈参数**！

## 一、双通道调用方式（自动适配任何 Agent 终端）

1. **优先通道（MCP Server 已挂载时）**：直接调用 `forecast-lab-optimizer` MCP 工具：
   - `optimize_forecast`：对原始预测草案执行可操作化体检、噪音陷阱识别、五类/四类校准概率估算、反事实方法寻优、**新技术四层同构扩散校准**，并生成《终局预测卡》；
   - `evaluate_tech_differentiation`：专门针对新技术判断执行“这次是否不一样”压力测试（支持传入当前渗透率 `current_penetration`、目标渗透率 `target_penetration`、年限 `horizon_years` 与存量/增量口径 `is_stock_scope`），输出 Bass S 曲线合理区间与必查实时瓶颈清单；
   - `query_reference_class`：查询同领域、同时间跨度的层级经验贝叶斯基准率与正反历史先例；
   - `bayesian_update_forecast`：输入正反双向新证据，执行事件轴/机制轴/时间轴阻尼对数赔率更新；
   - `audit_forecast_ledger` / `register_optimized_forecast` / `get_optimizer_benchmark`。
2. **通用零配置通道（任意终端 CLI 直接调用，零第三方依赖）**：
   ```bash
   # 1. 对预测草案执行完整优化（技术类命题会自动附带历史同构扩散曲线与实时瓶颈清单）
   python3 toolkit/forecast_optimizer.py optimize \
     --statement "<用户的原始预测表述>" \
     --domain "<领域>" \
     --horizon "<期限，如 2026-2030>" \
     --format markdown

   # 2. 单独针对新技术做“这次是否不一样” Bass 扩散斜率与物理周转墙校准
   python3 toolkit/forecast_optimizer.py tech-analog \
     --statement "到2029年底人形机器人取代50%汽车总装线工人" \
     --current-share 0.01 --target-share 0.50 --horizon-years 3 --stock
   ```

## 二、标准六步方法优化工作流（Agent 必循协议）

1. **Step 1 — 基线诊断与扫雷**：调用 `optimize_forecast`，检查有效预测置信度、规范要素完整度（`score_out_of_6` + `explicit_method_disclosed`）与五大噪音陷阱。
2. **Step 2 — 新技术“这次是否不一样”四层同构检验（技术/产业题必做）**：
   读取返回结果中的 `tech_differentiation_audit`：
   - 确认命题落在哪一层：**第 1 层纯比特消费协议**（2–5年可普及）、**第 2 层消费终端换机**（4.5–14.5年）、**第 3 层企业核心工作流重塑**（7.5–16年，发电机悖论：任务先变、岗位慢变），还是 **第 4 层重资产/电网/具身硬件/零容错强监管**（12–26年，最慢物理/立法短板锁死上限）；
   - 严格区分 **新增流量占比（Flow）** 与 **全社会存量保有量/总岗位替代（Stock）**；若要求速度超过历史同构前辈（如公有云、ERP、工业机械臂、电动车）的 **2.2 倍以上**，必须向用户拉响跨层速度透支警报，给出 `1.0x–1.5x` 历史校准合理渗透区间。
3. **Step 3 — 联网核查当下实时瓶颈参数（用今天的新事实修正历史斜率）**：
   对照 `realtime_parameters_to_fetch_now` 列出的 3 项指标（如变压器排队月数、POC 转年框付费留存率、整机 BOM 回本周期、适航/临床审批进度），利用联网搜索补齐**当下的真实行业基数**，判断本轮斜率究竟处于历史的 `0.8x`、`1.0x` 还是 `1.5x`。
4. **Step 4 — 选定并写出“主方法四步推导链 + 反校验透镜 + 承诺硬度”**：把实时查到的存量、流量、瓶颈数据填入引擎推荐的主方法四步推导链中。
5. **Step 5 — 二次校准验证并输出《终局预测卡》**：再次调用 `optimize_forecast` 确认陷阱清零、`6/6` 达标，向用户完整输出预测承诺、显式预测方法四步推导链、历史同构校准说明、10,745 库先验概率与证伪红线。
6. **Step 6 — 事前冻结入库与三轴复盘**：确认后调用 `register_optimized_forecast`（含 `method_derivation`）冻结入库。
