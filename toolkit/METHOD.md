# 可执行的预测研究方法

目标是建立“原文 → 可观察判断 → 证据 → 结论”的链条，分开记录预测结果与作者的思考方法。先保持结构简单，再逐轮补证据。

## 1. 抽取预测

可直接从 TXT 分段抽取，也可从书籍或访谈已有的候选短引文出发。保留原文位置、说话者、必要上下文及原文核验方式。一次抽取记录预测对象、方向、时间、条件和不确定语气。TXT 保留行号和字符偏移；PDF 保留原页码。

- 预测应指向说话时尚未确定、出版年之后、并且事后能够核验的结果。建议、目标、历史描述和反事实不能自动算预测。
- 抽取版本 v5 给每条候选一个 `claim_type`：`forecast`、`aphorism`（比喻、格言）、`normative`（规范建议、政策倡议）、`trivial`（几乎必然的仪式或程序）、`historical`（出版年之前的事件或历史解释）、`mechanism`（没有未来结果的机制说明）、`hypothetical`（过去的反事实、假设的战争情景）、`unclear`。写出变化方向的句子是 `forecast`，可以评分。比喻、建议、仪式、出版前历史、无结果的机制和假设情景从候选中排除，并在抽取报告里按类型计数。连变化方向都没有的句子降为 `unclear`，不进入命中率分母。
- 出版年用案例配置里的 `publication_year_proxy`。引文里的年份、年代和区间若全部早于出版年，又没有指向出版年之后的时间，就标为历史或过去反事实，不能当作后来应验。出版年当年的事件不自动排除。
- 可评分的预测必须写出什么会变化。原文写了时间则 `horizon_source=explicit`，`horizon` 只保留原文中的那段时间。没有写时间的方向性判断（如“差距将会扩大”）仍是 forecast：`horizon_source=implicit_publication_to_cutoff`，观察窗口是出版年到案例截止日。窗口内主要方向已经发生记为正确，方向相反记为错误；不因缺少作者日期改成暂无法判断，也不因此只给趋势符合。模型补写的日期不算 explicit。没有变化方向则 `resolvable=false`，不能判为正确。`confidence` 只记录作者语气所暗示的把握（high/medium/low/unknown），没有原文依据就是 unknown，不参与评分。
- 同一句里互相重叠的两段只保留先出现的一段，哪怕重叠不到较短一段的 80%。两段没有重叠时，即使在同一句里也各自保留。
- 没有 `extraction_version` 的旧抽取按 v4 读取：来源校验仍使用冻结的 v4 提示词，不要求 `claim_type`。已接受案例的判定不因这次规则追溯改写。
- “可能”不是某个固定概率；没有原始数字，就不编出70%之类的概率。
- 保留否定、让步、真正的如果条件和复合分项。作者对结果的因果解释，不自动成为额外的触发门槛。带有明确时间和结果的条件预测仍然可以是 forecast；没有时间的战争设想不是。
- 没有确切发言日期时，可以用出版年作为明确披露的代理；不能把已知出版前事件当作后来应验。
- 同一父记录不因拆出多个观察节点而重复增加命中次数。重复候选排除，相关判断保留关联信息。
- 核查侧：v5 记录若 `claim_type` 不是 forecast，或 `resolvable` 为 false，判定不能是“正确”。新的核查还会直接看引文；比喻、格言、必然仪式、出版前历史、无未来结果的机制、规范建议和假设情景，即使抽取标成了 forecast，也不能判为正确。方向性判断没有写出时间时，按出版年至截止日评分，窗口内方向发生可以为正确。

抽取阶段不提供事后证据。模型记录思考办法时，只归纳原文：`explicit` 为原文明示，`inferred` 为研究者推断，`unknown` 为摘录不足。

每条另存 `expanded_claim`：依据原文及所给上下文补全“他们、这个国家、不会”等代指和问答省略。保留原说话者、时间、否定、条件及可能性。`reference_resolutions` 逐项登记 `expression, referent, support_quote`；程序要求表达片段和支持引文逐字存在于所给文本。依据不足就用 `[指代待确认：…]` 和 `unresolved_references` 明示，不能靠常识、事后证据或旧摘要猜定。逐字匹配只能验证文本来源，代指解释是否成立仍要审阅。

## 2. 建立可观察口径与证据

先写清对象、指标、比较基准、观察窗口和会推翻判断的结果。作者没有精确阈值时，允许采用透明、合理的回顾性口径；采用代理指标时写清限制。

优先原始统计、官方制度文件、实际交付或实施记录，同时搜索反证。政策宣告不等于执行；GDP不等于居民收入；名义、实际、PPP等口径不能混用。一个有利指标不能代表所有主要分项。

每条证据记录URL、资料日期、事实时期、摘要、限制和本地文件SHA256。哈希证明保存内容没有变化，不证明来源本身准确。模型只依据任务包证据核查，不用训练记忆补写事实。

默认每条最多两轮补充检索；仍缺证据就记清缺口，避免一条记录阻塞整本书。主题相同的预测复用证据。

## 3. 五类结论

|类别|使用条件|
|---|---|
|正确|主要结果在声明的范围内已符合|
|趋势符合|持续可观察变化支持主要方向，但长期终点或完整结果仍未实现|
|部分符合|分项、阶段或合理口径存在实质差异，不能统一判全对或全错|
|错误|主要可检验结果与预测相反|
|暂无法判断|仍不足以判断结果或趋势，或真实条件尚未确认|

趋势不要求每一年完全单调，但必须看完整窗口及近期反向变化，不能只挑两个有利年份。保留原始期限；单次波动、模型给出的未来数值和只有因果解释的句子，不算已观察趋势。

真正的条件没有触发，不能用另一种情境下的结果代替。若主要预测结果可以观察、附带机制无法识别，可评结果并在限制中说明因果未验证。

这不默认要求随机对照或净因果识别。原文没有阈值时，应先声明合理观察口径，再寻找支持与反证；不能只以“作者没给指标”结束可操作的条目。全称断言可被满足其条件的确切反例反驳，一个正例则不能证明普遍成立。复合命题仍检查全部主要结果：缺失分项如实保留，不把结果附带的原因、修辞或未验证机制另加为结果评分门槛。

报告分别展示候选处理数、绑定证据数与可判定数；没有绑定证据不等于完成搜证，结构通过也不等于研究完成。全部未决时应触发方法和搜证覆盖复查，不以强行改判消除未决。

## 4. 评估机制与“信号、噪声”

把指标口径、观察时期和条件固定下来，是减少事后挑选的第一步；保留相反证据、未决条目与每轮改判理由，是识别噪声的基础。

当前先报告五类数量和可评估覆盖率。趋势符合、部分符合都不折算0.5分；暂无法判断不算错，也不把“正确+趋势符合”称为最终准确率。

有作者明确概率且事件结果确定时，后续可使用 Brier：`mean((p - y) ** 2)`，并与同一组事件的历史基准比较。没有概率就不计算 Brier。独立性、时间窗口和选择偏差没有处理好之前，不做作者排行榜或跨书能力排名。

方法归因与结果分开：即使结果符合，也不证明作者提出的因果机制成立。当前结果属于回顾研究，不是预先登记的预测比赛。

## 5. 简单数据约定

每个案例有自己的 `config.json`、`data/claims.jsonl`、`data/evidence.jsonl` 和 `output/`。不依赖其他案例的数据。

最小候选记录：

```json
{"id":"p001-01","page":1,"quote":"原始短引文","context":"必要上下文","speaker":"作者","source_verified":true,"duplicate_of":null,"kind":"prediction","claim":"待抽取","time_text":"","condition_text":"","method":"","method_basis":"unknown","extraction":null,"review":null,"legacy":{"units":[]}}
```

`source_verified=true` 只能来自原文核验，不能因为模型输出看似合理就升级。TXT 导入以原始文本精确子串匹配核验引文，并记录 `source_verification.method=txt_exact_match` 与源文件哈希；这不代表人工校对、说话者归属或事实已经核验。`source_location` 保存 `type=txt, line_start, line_end, char_start, char_end, source_sha256`，字符偏移按解码后 Unicode 从0起算、右端不包含，保留 CRLF；`page=null`。整本 TXT 由使用者另外保存，程序不复制到案例目录。

`extraction_v2` 保存已接受的新版抽取及扩展观点；`assessment` 保存已接受评估，旧记录和导入前快照保留。补扩展观点不自动改判；若主要对象仍不确定，下一轮核查须保留归属/定义缺口。TXT 分段全部完成也不保证预测穷尽，长句边界和远距离指代仍可能漏抽或留待复核。

证据记录：

```json
{"id":"ev-001","url":"https://example.org/source","date":"2025-01-01","coverage":"2020—2024","excerpt":"实际观察摘要","limitation":"口径限制","local_archive":"data/sources/source.json","sha256":"该文件的真实SHA256","verified":true}
```

评估字段：`id, inclusion, verdict, basis, scope, reason, limitation, evidence_ids, method, method_basis, observation_end, future_time_text, condition_state, trend_aligned`。

- `inclusion`：forecast / nonforecast / duplicate；排除项的verdict为null。
- `basis`：endpoint / observed_window / conditional / future / definition / evidence / attribution / excluded。
- `condition_state`：unconditional / satisfied / not_met / unknown。正确和错误仍要求真实条件为 unconditional 或 satisfied。前提未知但后果或分项已有直接证据时，可以用部分符合（含趋势符合）并写明未证实的前提；这不能用来把缺少主要结果证据的条目评成部分符合。
- 为兼容既有记录，底层 `verdict=部分符合, trend_aligned=true` 显示为“趋势符合”。CSV读 `display_verdict`，统计读 `display_verdicts`，这五类互不重叠；不要把兼容四类与展示五类相加。
- 明确未来终点保存在 `future_time_text`；若已有趋势，用observed_window/conditional；只有趋势和结果都不能判断时才用future。

补充研究可写入 `output/review/research_*.jsonl`，每条包含 `id, change_reason, evidence_ids, recommendation`；recommendation可以是完整评估建议。模型把研究建议当参考，不当金标准。

## 6. 并行执行与验收

不同批次并行；同一批必须先抽取、再核查。待判断复核直接复用已接受的抽取。默认12并发、最多20，依据请求大小自动拆批；费用预留是线程安全的，失败原响应保留，未知状态不盲目重试。

全书首评可用 `--assess-only` 复用来源和版本校验合格的 TXT 抽取，用 `--share-contexts` 在同批中共享完全相同的上下文；每条候选仍绑定自身原文和证据范围。TXT 每段完成即输出检查点，最终全量导入规则不变。只允许忽略空白后唯一匹配的引文恢复，修复轨迹保留；它不是语义校验或人工原文核验。

预算被在途请求暂占时等待释放；无可释放的在途请求仍不足时拒绝。不同 Runner 的账本仍独立，整书多阶段预算由调度者汇总，不能把每阶段预算相加后称为单一全局上限。

程序检查：ID覆盖和唯一性、证据引用范围、存档哈希、日期截止、条件状态、五类互斥展示及密钥脱敏。语义对应关系、代理指标是否合理、预测与因果的边界仍需要逐条评阅。改判记录保留旧判定、新判定、证据及原因。
